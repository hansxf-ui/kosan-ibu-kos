## 2. Temuan + AKAR + perbaikan

### A. Keamanan / integritas

**A1. Jalur tulis publik (KRITIS — cacat utama).**
- *Gejala:* siapa pun bisa klaim kamar pakai nama ngasal.
- *AKAR:* desain mempercayakan shared state pada tulis publik tanpa
  autentikasi, padahal model kepercayaan format ini cuma punya SATU penulis
  terpercaya: cerita (pemilik/Vesper lewat episode). Pengunjung bukan penulis
  cerita — mereka jadi penghuni LEWAT cerita (follow + komen di episode).
- *Perbaikan:* hapus SELURUH jalur tulis — Firebase SDK, config, listener,
  transaction, `klaimKamar`. Situs kembali sepenuhnya statis. Penghuni
  bersama = data baked-in (`RESIDENTS` di `app.js`).

**A2. Troll bisa mengunci (squat) ke-10 kamar, tanpa jalan keluar.**
- *Gejala:* first-come-first-served + tanpa moderasi/reset = satu orang bisa
  mengklaim semua kamar dalam hitungan detik dengan nama sampah, dan penghuni
  beneran terkunci di luar selamanya.
- *AKAR:* sama dengan A1, diperparah karena tidak ada otorisasi, moderasi,
  maupun tombol reset. Transaction hanya mencegah overwrite — bukan tulis
  sampah.
- *Perbaikan:* tidak ada lagi state bersama yang bisa ditulis publik, jadi
  squat tidak mungkin terjadi. (Lihat juga A3 untuk sisa lubang di rules.)

**A3. Rules RTDB masih mengizinkan tulis publik via REST langsung.**
- *Gejala:* walau situs sudah tidak menulis, siapa pun yang tahu URL RTDB
  masih bisa PUT sampah ke `/rooms/kosan-ibu-kos/members` lewat curl.
- *AKAR:* rules ter-deploy (`.write` publik di children `meta/playback/
  members/chat` di bawah `/rooms/$kode`) dibuat untuk Nobar, dan path kosan
  menumpang namespace yang sama.
- *Status saat ini:* **TIDAK BERBAHAYA** — tidak ada yang membaca path itu
  (situs tidak lagi mereferensikan Firebase; `members` = null, diverifikasi).
  Sampah yang ditulis ke sana tidak terlihat di mana pun.
- *Perbaikan oleh agent:* TIDAK BISA (butuh console Firebase pemilik).
  Rekomendasi + langkah persis ada di bagian 4.

**A4. XSS via nama — TIDAK DITEMUKAN.**
- *Pemeriksaan:* semua nama dimasukkan HANYA lewat `textContent` /
  `setAttribute` (kartu, panel detail, tombol denah, aria-label). **Nol**
  pemakaian `innerHTML` di kode (grep + tes stub yang MELEDAK kalau
  `innerHTML` dipakai — 50 tes jalan bersih). `html2canvas` me-render DOM
  sebagai teks. Deep link `?nama=` mengalir ke `input.value` lalu jalur
  `textContent` yang sama.
- *Perbaikan:* tidak perlu; disiplin `textContent` dipertahankan di
  penulisan ulang (dan ditegaskan di komentar kode).

**A5. Impersonasi (klaim kamar atas nama orang lain).**
- *Dulu:* siapa pun bisa klaim kamar dengan nama komentator beneran.
- *Sekarang:* mustahil — hanya Vesper yang menempatkan nama, lewat deploy.
  Preview atas nama orang lain hanya tampil di HP pelaku sendiri dan
  berlabel PREVIEW.

**A6. Config Firebase terekspos di JS.**
- *Fakta:* `apiKey` dkk. adalah nilai client PUBLIK (bukan rahasia — sesuai
  komentar di `~/workspace/nobar/firebase-config.js`). Risiko sebenarnya
  bukan kerahasiaan, melainkan nilai itu adalah kunci tulis publik (lihat
  A1/A3).
- *Perbaikan:* tidak ada lagi config apa pun di situs (grep live: 0).

**A7. Fallback "mode lokal" diam-diam.**
- *Gejala lama:* kalau CDN Firebase mati, situs menghitung kamar lokal TANPA
  mencatat — pengunjung mengira kamarnya tercatat, padahal tidak.
- *AKAR:* dua jalur kode dengan semantik berbeda (tercatat vs tidak).
- *Perbaikan:* satu jalur saja (lokal, jujur). Tidak ada lagi ketergantungan
  jaringan untuk alur utama.

**A8. Alur klaim menunggu CDN tanpa timeout.**
- *Gejala lama:* `assign()` menunggu `muatFirebase()` (dynamic import)
  tanpa timeout — CDN lambat = form menggantung, pengguna tidak tahu kenapa.
- *Perbaikan:* dihapus bersama SDK. Preview sekarang instan (murni hitungan
  lokal).

**A9. Share-link spoofing (`?nama=`).**
- *Fakta:* tautan `?nama=X` menampilkan kartu nama X ke siapa pun yang
  membukanya — itu fitur Bagikan yang dimaksudkan.
- *Risiko sisa:* DITERIMA — kartu berlabel PREVIEW dan tidak memengaruhi
  denah bersama. Tidak ada jalan bagi tautan untuk menaruh nama di denah.

## 4. YANG TIDAK BISA DIPERBAIKI AGENT — rules RTDB (butuh console pemilik)

**Keadaan:** situs sudah aman tanpa ini (tidak ada yang membaca path
kosan). Ini hardening defense-in-depth: mengunci pintu yang sudah tidak
dipakai siapa pun, supaya tidak bisa dipakai orang iseng di masa depan.

**JSON rules (PENGGANTI SELURUH rules yang ada — mempertahankan perilaku
Nobar, menambah pengecualian untuk kode `kosan-ibu-kos`):**

```json
{
  "rules": {
    "rooms": {
      "$kode": {
        ".read": "$kode !== 'kosan-ibu-kos'",
        "meta": { ".write": "$kode !== 'kosan-ibu-kos'" },
        "playback": { ".write": "$kode !== 'kosan-ibu-kos'" },
        "members": { ".write": "$kode !== 'kosan-ibu-kos'" },
        "chat": { ".write": "$kode !== 'kosan-ibu-kos'" }
      }
    }
  }
}
```

**Kenapa bentuk ini (bukan blok literal `"kosan-ibu-kos": {...false}`):**
di RTDB, izin yang sudah diberikan di satu level tidak bisa dicabut oleh
aturan `false` di level yang sama — jadi pengecualian HARUS ditulis sebagai
syarat di wildcard `$kode` itu sendiri. `$kode` adalah variabel wildcard
yang berlaku sampai ke aturan anak (`meta`/`members`/…).

**Langkah console (persis):**

1. Buka Firebase console → proyek **nobar-7a37d** → **Build → Realtime
   Database** → tab **Rules**.
   Tautan langsung (kalau tidak mendarat di tab Rules, pakai navigasi di
   atas): https://console.firebase.google.com/project/nobar-7a37d/database/nobar-7a37d-default-rtdb/rules
2. Ganti SELURUH isi editor dengan JSON di atas → klik **Publish**.
3. Verifikasi (2 menit):
   a. Tulis ke path kosan HARUS ditolak — dari Termux/komputer mana saja:
      `curl -X PUT "https://nobar-7a37d-default-rtdb.asia-southeast1.firebasedatabase.app/rooms/kosan-ibu-kos/members/1.json" -d '{"name":"TES"}'`
      → harus `{"error":"Permission denied"}` (HTTP 401).
   b. Nobar tetap jalan: buka sebuah ruang Nobar, pastikan playback
      sinkron + chat tetap bisa dikirim.
4. Kalau 3a masih HTTP 200, rules belum kepublish — ulangi langkah 2 dan
   pastikan menekan **Publish** (bukan cuma menyimpan).

**Peringatan jujur:** JSON di atas menggantikan SELURUH rules. Saya tidak
bisa membaca rules yang sedang ter-deploy lewat API — sumber saya adalah
`~/workspace/nobar/README.md` + hasil probe (tulis members → 200, baca
root → 401, DELETE level `$kode` → 401; semuanya konsisten dengan rules
di README). Sebelum Publish, buka tab Rules dan bandingkan: kalau di sana
ada path di luar `/rooms` yang dipakai sesuatu, JANGAN timpa mentah-mentah
— kabari Vesper dulu supaya JSON-nya disesuaikan. Node
`/rooms/kosan-ibu-kos/members` saat ini `null`, jadi tidak ada data yang
hilang.
